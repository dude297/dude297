FLAGSHIP HARDWARE PROJECT / IN DEVELOPMENT

Modular Memory Expansion Platform

What if unused laptop memory could become an affordable, host-accessible memory tier? I’m developing a staged DDR4 and FPGA platform to investigate that question, starting with module characterization and working toward PCIe-connected device memory.

01 / ENGINEERING EVIDENCE

From module identity to a testable memory interface.

Development starts with a USB-C, read-only Serial Presence Detect (SPD) reader. SPD describes a module’s identity, organization and timings; it does not expose the DRAM array itself.

FPGA / SIMULATION

Behavioral memory tests, corruption detection and a LiteDRAM simulation checkpoint. Real DDR4 training and read/write validation remain pending.

READ-ONLY CHECK

Real SPD data

Read and checked SPD data from an installed laptop memory module using the existing host, not the custom board.

No custom PCB has been fabricated or powered. The project has not yet demonstrated physical FPGA-attached DDR4 or a PCIe memory device.

02 / TARGET ARCHITECTURE

Keep the memory controller close to the memory.

Linux hostDriver / application API
↔
FPGA endpointPCIe DMA / DDR4 controller + PHY
↔
DDR4 SO-DIMMOne validated module first

This is a proposed architecture. Ordinary PCIe device memory is not transparent CPU system RAM. A host driver and application must explicitly manage access; potential uses include application-managed buffers and an experimental memory tier for memory-constrained workloads.

03 / DEVELOPMENT ROADMAP

01 · Characterize DDR4 modulesIn development — review and fabricate the read-only SPD board, then validate capacity, rank, device width, timings and CRC across modules.
02 · Validate one physical DDR4 interfaceSimulation underway — select a documented DDR4-capable FPGA platform, establish PHY training, then demonstrate reliable reads and writes.
03 · Demonstrate PCIe device memoryPlanned — implement host DMA and benchmark data integrity, throughput and latency on Linux.
04 · Evaluate modular expansionPlanned — assess independently controlled modules, compatibility, throughput and power before adding more channels.
05 · Investigate CXL Type-3 memoryExploratory — study coherent memory expansion and tiering using compatible host and endpoint hardware and IP. Not a promised hardware deliverable.

I intend to publish reviewed design files and reproducible results once publication and licensing decisions are complete.
