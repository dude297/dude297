READER ARCHITECTURE

Start with what the module can tell us.

Serial Presence Detect (SPD) is a small EEPROM containing the module’s identity, geometry and timing parameters. The reader is a way to characterize mixed SO-DIMMs before choosing a memory-controller configuration.

A concrete design change: the power front end.

The early USB design fed several chips directly from VBUS. Rev B.1 adds a regulated 3.3 V front end and a reset supervisor so the USB bridge has a controlled supply and reset sequence. Power calculations and transient simulations guided that change; rail behavior, USB enumeration and suspend current still need bench measurements.

The PCB candidate is frozen for fabrication review. The next useful artifact is a measured bring-up record: rails, reset timing, enumeration and repeatable SPD reads.

FPGA EXPERIMENTS

Test the logic before connecting DDR4.

The first RTL tests use a behavioral memory model. Randomized latency and back-pressure check the tester’s handshake behavior; deliberate corruption checks whether it reports the correct failing address.

BEHAVIORAL MODEL

One corrupted word detected

The test reports one error at address 0x5A. A stuck-bit model reports 128 errors. These check the tester, rather than a physical DDR4 interface.

LITEDRAM FUNCTIONAL SIMULATION

Module geometry in the model

Further simulations exercise rank and address mappings derived from an installed module’s SPD data, with negative controls for incorrect mappings.

The current UPduino is for toolchain practice; it cannot drive DDR4. Physical validation needs a documented DDR4-capable FPGA platform and a supported controller/PHY.

NEXT STEPS

One physical interface before a bigger system.

  1. Validate the reader. Finish fabrication review, assemble the board and measure the bring-up sequence before reading spare modules.
  2. Prove FPGA-attached DDR4. Choose a supported development platform and demonstrate repeatable training and data-integrity tests with one module.
  3. Explore host access. PCIe DMA is the later device-memory goal. Ordinary PCIe device memory requires explicit host access; it does not become transparent CPU RAM. CXL is a separate research direction.

Linux PCIe and CXL emulation experiments also exist, but they do not establish a working physical endpoint.
