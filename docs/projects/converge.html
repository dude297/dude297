CASE STUDY / 01

Converge

A durable outcome layer for AI agents operating across systems where partial success is more dangerous than a clean failure.

TYPEAgent infrastructure
STATUSHackathon prototype
STACKGemini / Supabase / Stripe
FOCUSReliability + execution

01 / PROBLEM

Agents can reason correctly and still leave the world wrong.

A support agent may decide to issue a refund and resolve a case, but those mutations happen in different systems. If execution dies after Stripe succeeds and before the database updates, blindly retrying the model can duplicate a side effect. Converge treats the desired business outcome—not the model's procedural trace—as the durable object.

FAILURE MODE

Partial mutation

External systems can diverge after a crash, timeout, or interrupted execution.

BOUNDARY

Reasoning ≠ authority

The model chooses a target outcome; deterministic code owns allowlisted mutations.

RECOVERY

Observe before retry

Authoritative state is re-read before deciding which action, if any, remains.

SAFETY

Ownership preflight

Mutation targets must belong to the authorized customer/resource set.

Converge stores the declared outcome before mutation. Reconciliation compares that outcome against live Stripe and Supabase state, then executes only the minimal remaining safe repair.

03 / DECISIONS

Engineering choices that matter.

Persist intent before side effectsThe desired outcome survives process failure and can be inspected by a later worker.
Make reconciliation deterministicLLM reasoning is not used to decide whether a requirement is currently satisfied.
Design the demo around a real failureExecution intentionally stops after a real Stripe test-mode refund so recovery is observable rather than hypothetical.
Characterize the correctness boundaryOwnership validation prevents unauthorized mutation; it does not prove the agent selected the semantically correct same-customer charge.
