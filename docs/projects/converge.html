CASE STUDY / 01

Converge

Durable outcome infrastructure for AI agents operating across systems where partial success is more dangerous than a clean failure.

TYPEAgent infrastructure
STATUSWorking prototype
STACKGemini / Supabase / Stripe
FOCUSReliability + execution

01 / PROBLEM

Agents can reason correctly and still leave the world wrong.

A support agent may decide to issue a refund and resolve a case, but those mutations happen in different systems. If execution dies after Stripe succeeds and before the database updates, blindly retrying the model can duplicate a side effect. Converge treats the desired business outcome—not the model's procedural trace—as the durable object.

FAILURE MODE

Partial mutation

External systems can diverge after a crash, timeout, or interrupted execution.

BOUNDARY

Reasoning ≠ authority

The model chooses a target outcome; deterministic code owns allowlisted mutations.

RECOVERY

Observe before retry

Authoritative state is re-read before deciding which action, if any, remains.

SAFETY

Ownership preflight

Mutation targets must belong to the authorized customer/resource set.

04 / DECISIONS

Engineering choices that matter.

Persist intent before side effects The desired outcome survives process failure and can be inspected by a later worker.
Make reconciliation deterministic LLM reasoning is not used to decide whether a requirement is currently satisfied.
Separate semantic correctness from authorization Ownership checks prevent mutation outside the authorized customer set. They do not prove the agent chose the correct same-customer business target.
Prove coordination across workers A second worker finds the satisfied durable Outcome and performs zero new external mutations.
