DayBridge

Finding an activity is only the first step. DayBridge checks time, travel, cost, and access so an older adult can turn a recommendation into a practical plan.

ROLEDeveloper · hackathon team project
STATUSHACKATHON PROTOTYPE · SIMULATED PROVIDERS

01 / THE PROBLEM

An appealing recommendation can still be impossible to attend.

The planner considers availability, cost, mobility, transport, hearing, and group preferences. It explains what blocks an outing and proposes a practical alternative. Coordination requires explicit approval and provider confirmation before a plan can become ready.

02 / THE SYSTEM

From input to a checked result.

Check what fitsA deterministic engine ranks activities and preserves unknown accessibility information.
Propose supportA ride or invitation is a proposed action with a named recipient and scope.
Confirm readinessRequested support stays pending until a simulated provider confirms it.
Recover from changesA cancelled ride revokes readiness. The person reviews and confirms a revised plan.

Next.js · React · TypeScript · Zod · Vitest

03 / EVIDENCE & LIMITS

What has been demonstrated.

Deterministic activity matching, explained barriers, approval-scoped coordination, and simulated ride cancellation recovery. Public preview and local coordination demo have different capabilities.

The public preview opens at the root URL; its /demo route currently returns 404. The full coordination walkthrough is documented for a local build with simulated providers. No real rides, messages, payments, bookings, or attendance confirmations are performed.
