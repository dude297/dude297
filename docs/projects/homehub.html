HomeHub

A local-first distributed systems project built around durable state, bounded execution, explicit release authority, and small edge devices.

TYPESystems infrastructure
STATUSPrivate / active
STACKPython / Linux / SQLite / Pi
FOCUSDistributed systems

01 / PROBLEM

Home automation gets fragile when control, state, and recovery are implicit.

HomeHub treats the house like a small distributed system rather than a pile of scripts. The core owns durable state and execution policy; edge devices expose bounded capabilities; release state is explicit; and automation is designed to fail closed rather than widen authority for convenience.

CORE

Durable local state

SQLite-backed state and explicit protocol contracts preserve system truth locally.

WORKERS

Bounded execution

Worker sessions, leases, cancellation, and recovery are constrained by server-owned policy.

EDGE

Small-node services

Raspberry Pi nodes handle DNS, networking, storage, messaging, and edge workflows.

RELEASES

Immutable promotion

Candidate identity, validation, staging, promotion, and rollback are treated as separate authority steps.

03 / DECISIONS

Engineering choices that matter.

Local state stays authoritativeThe system does not require a cloud control plane to know what happened locally.
Lease expiry does not grant replay authorityTimeout is evidence of uncertainty, not permission to duplicate work.
No arbitrary remote shell surfaceCapabilities are modeled as bounded operations rather than general command execution.
Release evidence is immutableExact candidate identity and validation evidence are preserved before promotion.
